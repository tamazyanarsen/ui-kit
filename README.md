# UI-кит

Библиотека UI-компонентов, собранная по Figma-макетам. Здесь можно посмотреть все компоненты живьём, их состояния и варианты — через **Storybook**.

Эта инструкция — для тех, кто хочет посмотреть или проверить компоненты локально. После первоначальной настройки никаких команд вводить не нужно — только двойной клик по готовым скриптам.

## Что нужно установить (один раз)

1. **Node.js** — без него ничего не запустится.
   Скачать: https://nodejs.org — выбрать версию **LTS** (рекомендуемая).
   При установке ничего специально настраивать не нужно — везде «Next» / галочки по умолчанию.

2. **Способ получить код** — один из вариантов ниже, в разделе «Как получить код»:
   - на **Mac** самый простой путь вообще ничего заранее ставить не требует (Git скрипт поставит сам);
   - на **Windows** удобнее всего **GitHub Desktop**: https://desktop.github.com

После установки может понадобиться перезапустить компьютер.

## Как получить код

### Mac — быстрее всего: один скрипт делает всё сам
Не нужно заранее ставить ни Git, ни GitHub Desktop — скрипт сам поставит Git, если его нет, склонирует проект на Рабочий стол и откроет папку.

1. Открыть Terminal (`Cmd + Space`, ввести `Terminal`, нажать `Enter`).
2. Вставить в него эту строку и нажать `Enter`:
   ```
   curl -fsSL https://raw.githubusercontent.com/tamazyanarsen/ui-kit/main/scripts/init-mac.command | bash
   ```
3. Если появится системное окно про установку Git (Command Line Tools) — нажать «Установить» и подождать, скрипт сам продолжит после того, как установка закончится.

После этого откроется папка с проектом на Рабочем столе — дальше см. раздел «Запуск Storybook» ниже.

### GitHub Desktop (Windows и Mac)
1. Установить GitHub Desktop: https://desktop.github.com
2. Открыть GitHub Desktop, залогиниться своим GitHub-аккаунтом.
3. `File → Clone repository`.
4. Вставить ссылку: `https://github.com/tamazyanarsen/ui-kit`.
5. Выбрать папку на компьютере и нажать `Clone`.

## Запуск Storybook

В скачанной папке проекта лежит папка `scripts` с двумя файлами. Нужен только один из них — под свою систему:

- **Windows** — `scripts\start-storybook.bat`
- **Mac** — `scripts/start-storybook.command`

Дважды кликнуть по нужному файлу. Откроется чёрное окошко — это нормально, не закрывать его, пока нужен Storybook (можно свернуть). В первый раз запуск займёт пару минут — скрипт сам поставит всё необходимое, дальше будет быстрее. По завершении в браузере откроется Storybook (обычно http://localhost:6006).

> **Mac**: при самом первом запуске система может показать предупреждение «нельзя открыть, т.к. издатель не подтверждён». Это нормально для собственных скриптов — правый клик по файлу → `Открыть` → в появившемся окне ещё раз `Открыть`. Дальше будет открываться обычным двойным кликом без вопросов.

## Как обновиться (подтянуть новые компоненты)

Периодически в проекте появляются новые или обновлённые компоненты. Чтобы их получить:

1. Дважды кликнуть по скрипту обновления:
   - **Windows** — `scripts\update-project.bat`
   - **Mac** — `scripts/update-project.command`
2. Если Storybook был открыт — закрыть его окошко и запустить заново через `start-storybook`.

> ⚠️ **Не редактируйте файлы в этой папке напрямую.** Если что-то поменять локально, обновление может перестать работать. Если это случайно произошло — проще всего попросить помочь разработчика, либо удалить папку с проектом и склонировать заново.

## Шпаргалка

| Файл | Что делает |
|---|---|
| `scripts/init-mac.command` | Только для самого первого раза на Mac — ставит Git (если нужно) и клонирует проект |
| `scripts/start-storybook.bat` / `.command` | Открыть/запустить Storybook |
| `scripts/update-project.bat` / `.command` | Подтянуть новые компоненты |

## Если что-то не работает

- **Окошко сразу закрылось / ничего не произошло** — Node.js не установлен, либо нужно перезапустить компьютер после установки.
- **Порт 6006 занят / Storybook не открывается** — закрыть предыдущее окошко со Storybook (если оставалось открытым) и запустить скрипт заново. Если не помогает — перезапустить компьютер.
- **Mac: «Permission denied» при двойном клике** — такое почти не случается при обычном клонировании через GitHub Desktop, но если увидели эту ошибку — напишите разработчику, это можно быстро починить.
- **Что-то ещё непонятное** — написать разработчику, приложив скриншот окошка с ошибкой.
