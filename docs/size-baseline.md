## 2. Состав `index.css` — причина раздутости

Бриф предполагал, что CSS плохо жмётся из-за полного набора утилит Tailwind
либо из-за отключённой минификации. **Обе гипотезы неверны.**

| Что внутри | raw | доля |
|---|---:|---:|
| base64 шрифтов (5 × woff2, Object Sans) | 212.0 | 33% |
| base64 PNG (2 иллюстрации NPS) | 264.0 | 42% |
| собственно CSS | 160.7 | 25% |

Собственно CSS: **160.7 raw / 24.6 gzip / 20.0 brotli** — сжатие в 6.5 раза,
то есть совершенно нормальный минифицированный Tailwind-вывод. Аномальным
выглядел только суммарный файл: base64 не сжимается, и он тянул среднее вниз.

**Причина инлайна — библиотечный режим Vite.** В `build.lib` Vite инлайнит
ассеты принудительно, `assetsInlineLimit` при этом игнорируется. Проверено
экспериментом: сборка с `assetsInlineLimit: 0` дала байт-в-байт тот же
результат (651.48 kB / 3771.72 kB). Сборка того же входа **без** `build.lib`
вынесла ассеты файлами и дала CSS **175.1 raw / 26.8 gzip** плюс 17 отдельных
файлов ассетов.

Литеральных `data:image/png;base64` в исходниках нет — все ассеты приходят
обычными `import`, так что проверка из брифа (`grep -rn "data:image/png;base64" src/`)
ничего не находит, и поднятого `assetsInlineLimit` в конфиге тоже нет.

## 4. Что реально платит потребитель

Главная метрика. Пробное приложение импортирует **одну кнопку** и собирается
с `react`/`@base-ui` в external.

| Против чего собран пробник | raw | gzip | иконок в бандле |
|---|---:|---:|---:|
| текущий `dist` (один файл) | 1905.9 | 582.1 | 505 |
| сборка с `preserveModules` | 53.9 | 13.7 | 2 |

PNG в обоих случаях вытрясаются (`data:` в бандле пробника нет) — то есть
ассеты бьют по весу самого пакета и по времени парсинга, но не по конечному
бандлу того потребителя, который иллюстрации не использует.

**Почему одна кнопка тянет 505 иконок.** `src/components/ui/icon/icon.tsx`
собирает реестр глифов на верхнем уровне модуля: `import * as glyphs from "@/icons"`
и цикл `for (const [name, value] of Object.entries(glyphs))`. При сборке в один
файл границы модулей стираются, этот цикл попадает в общий скоуп `index.js` и
удерживает ссылки на все 505 глифов — tree-shaking у потребителя снять их не
может. Barrel `src/icons/index.ts` сам по себе тут вторичен.

|---|---:|---:|---:|

## 6. Выводы для плана работ

1. Целевые метрики «один компонент + одна иконка < 25 КБ gzip» достигаются
   переключением сборки на `preserveModules` — 13.7 КБ gzip уже сейчас, до
   какого-либо распила на пакеты.
2. Ассеты не выносятся флагом `assetsInlineLimit`. Нужен либо выход из
   `build.lib`, либо отказ от импорта бинарников в JS-граф (URL + статические
   файлы пакета).
3. Реестр в `Icon` — отдельная и обязательная правка: без неё гранулярность
   иконок не даст ничего, если компонент `Icon` попадёт в граф потребителя.
4. Цель «CSS < 20 КБ gzip» уже выполняется содержимым (24.6 gzip / 20.0
   brotli при полном наборе утилит кита) — как только из файла уедут шрифты и
   PNG. Пересборка Tailwind на стороне микрофронта для этой цели не требуется.
5. `lucide-react` числится в `dependencies`, но в коде не используется — в
   исходниках только упоминания в комментариях.
