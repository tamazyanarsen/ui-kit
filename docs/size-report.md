# Журнал оптимизации `@core/ui-kit`

Отсчёт — `docs/size-baseline.md` (коммит `2232d47`). Размеры в КБ.

## Фаза 2+4 (частично): режим сборки, вынос ассетов, subpath-импорты

Фазы «ассеты» и «упаковка» из брифа выполнены вместе: ассеты выносятся не
флагом, а сменой режима сборки, поэтому разделить их нельзя.

### Что платит потребитель

Пробник собран против **реально упакованного пакета** (`npm pack` +
`npm install` тарбола), а не через alias — иначе `exports` не проверяется.
`react`/`@base-ui` в external.

| Сценарий | было raw | было gzip | стало raw | стало gzip |
|---|---:|---:|---:|---:|
| `import { Button } from "@core/ui-kit"` | 1905.9 | 582.1 | 53.3 | **13.7** |
| `@core/ui-kit/button` + `@core/ui-kit/icons/lock` | — | — | 55.8 | **14.9** |
| Button + Input + Table по subpath | — | — | 159.8 | 42.7 |

Иконок в бандле пробника: было 505, стало 2–3 (только те, что реально нужны
кнопке). Цель брифа «компонент + иконка < 25 КБ gzip» достигнута.

### Артефакты пакета

| Файл | было raw / gzip / brotli | стало raw / gzip / brotli |
|---|---|---|
| `dist/index.js` | 3683.3 / 1768.1 / 1634.9 | 11.7 / 3.1 / 2.7 |
| `dist/index.css` | 636.2 / 385.6 / 377.0 | 171.0 / 25.8 / 21.0 |
| `dist/components/ui/button/index.js` | — | 0.1 / 0.1 / 0.1 |
| `dist/icons/lock.js` | — | 2.3 / 1.1 / 0.9 |

CSS похудел на 94% по gzip: из него уехали 5 шрифтов (158.7 КБ woff2) и
2 PNG. `data:` URI в `dist/**/*.js` не осталось ни одного — критерий приёмки
Фазы 2 по этому пункту выполнен.

Суммарно на диске на момент этого шага: JS 2036.2, декларации 306.4,
PNG 1348.6, шрифты 158.7, 1609 файлов. Сумма выросла относительно двух монолитов — это ожидаемо
(модуль на файл + отдельные ассеты) и на вес у потребителя не влияет: он
берёт только то, что импортировал.

### Сделано

1. Сборка переведена с `build.lib` на обычный режим с `preserveModules`.
   Причина отказа от `build.lib` — принудительный инлайн ассетов, см.
   `docs/size-baseline.md`.
2. `preserveEntrySignatures: "strict"` — иначе вне библиотечного режима
   публичные экспорты вытрясаются и `index.js` схлопывается в 20 байт.
3. Точки входа: корневой бочонок + бочонок каждого из 63 компонентов, чтобы
   `@core/ui-kit/button` резолвился в реальный файл.
4. `assetsInlineLimit: 0` — теперь работает, потому что режим не библиотечный.
5. `exports` дополнен subpath-мапами `./*` (компоненты) и `./icons/*`
   (иконки). Корневой `"."` сохранён — обратная совместимость не нарушена.
6. Декларации: в `vite-plugin-dts` добавлен `src/icons/**`, иначе у иконок
   по subpath не было бы типов.
7. Удалён `lucide-react` из `dependencies` — в коде не используется ни разу
   (остались только упоминания в комментариях).

### Не сделано в этой фазе

- Растр не пережат — сделано следующим шагом, см. ниже.
- SVGO по иконкам не прогонялся.
- Реестр глифов в `Icon` по-прежнему тянет весь набор — это безопасно
  ровно до тех пор, пока потребитель не импортирует сам `Icon`.

### Отклонения от брифа (сборка)

| Пункт брифа | Что оказалось на деле |
|---|---|
| 2.1 «выключить инлайн через `assetsInlineLimit: 0`» | В `build.lib` флаг игнорируется. Помогает только выход из библиотечного режима. |
| Фаза 4 «распил на 7 пакетов ради гранулярности» | Гранулярность даёт `preserveModules` + `exports` внутри одного пакета. Распил остаётся оправдан для `singleton` у runtime, но не для веса. |
| «CSS раздут из-за полного набора утилит Tailwind» | Утилиты весят 24.7 КБ gzip. Раздували base64 шрифтов и PNG. |

## Фаза 2 (остаток): пережатие иллюстраций

### Что было и стало

| Группа | PNG (было) | AVIF | WebP |
|---|---:|---:|---:|
| `status-screen` (10 кадров) | 555.5 | 46.3 | 60.3 |
| `error-page` (2 маскота) | 595.0 | 38.2 | 79.7 |
| `nps` (2 иллюстрации) | 197.9 | 12.6 | 24.2 |
| **в поставке (`dist/assets`)** | **1348.6** | **97.2** | **164.3** |

Браузер грузит один формат, а не оба: с AVIF это **97.2 КБ вместо 1348.6** —
в 13.9 раза меньше. На диске лежат оба формата (261.5 КБ, в 5.2 раза меньше
исходного) — это цена запасного пути.

### Сделано

1. `scripts/convert-illustrations.mjs` — пережатие PNG → AVIF (q55) + WebP
   (q82) через ImageMagick. Отдельной зависимости (`sharp`) не потребовалось:
   `magick` уже есть в окружении и умеет оба формата.
2. Качество подобрано по сетке 45/55/65 сравнением с оригиналом: на 55
   отличий не видно, RMSE 1.8%.
3. `src/lib/picture.tsx` — общая обёртка `<picture>` с `display: contents`,
   чтобы классы и позиционирование остались на самом `<img>` и раскладка не
   поменялась. Публичный API компонентов не тронут.
4. `StatusIllustration` и `ErrorPageIllustration` переведены на `<Picture>`.
5. NPS получает картинку фоном через CSS-переменную, там `<picture>` не
   применить: базовое значение — WebP, AVIF подставляется через
   `@supports (background-image: image-set(... type("image/avif")))`.
6. PNG удалены из поставки: в `dist` их больше нет ни одного.

Проверено в браузере: Status Screen (14 картинок), Error Page и NPS грузят
AVIF, битых изображений нет; NPS-фон — 6.9 КБ AVIF вместо 114 КБ PNG.

### Отклонения от брифа (иллюстрации)

| Пункт брифа | Что оказалось на деле |
|---|---|
| 2.3 «`status-screen` — плоская векторная графика, перевести в SVG» | Это 3D-рендеры с градиентами, бликами и тенями (264×204, выгружены из Figma как растровые заливки). Вектором они быть не могут, SVG-исходников не существует. Переведены в AVIF/WebP, как и остальные иллюстрации. |
| 2.2 «ожидаемый результат 20–40 КБ на изображение» | Достигнуто с запасом: 16.4–21.8 КБ AVIF для крупных маскотов, 4.4–4.8 КБ для кадров Status Screen. |
| «вес ассетов на диске снизить в 8 раз» | В поставке — в 13.9 раза по фактической загрузке (один формат), 5.2 раза по сумме двух форматов. Хранить только AVIF без запасного WebP не стали. |

Исходные PNG оставлены в `src/assets` как мастер-копии: в пакет они не едут
(`files: ["dist"]`), а повторная конвертация из lossy-формата ухудшила бы
качество.
